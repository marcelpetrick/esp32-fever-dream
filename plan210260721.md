# Automation-Only Recognition Remediation Plan - 2026-07-21

The goal is to close the open recognition-quality fields without manual image labeling. Human effort is not part of this plan. All labels must come from programs, local vision models, OCR consistency checks, sensor/temporal constraints, or synthetic/derived data.

## Current blockers

The latest trained model is exported, but not deployable:

- Test digit accuracy: 86.68%.
- Full-frame digit accuracy: 89.82%.
- Full-reading exact accuracy: 12.78%.
- Negative examples: 0.
- Deployment gate: blocked.

Root causes:

1. Bulk Ollama labels are not strong enough as single-model ground truth.
2. Gas-field leading blanks are modeled as digits, which creates bad crop labels.
3. No negative/ambiguous set exists.
4. Dependency freshness is not reproducibly checked.
5. Firmware still contains prototype confidence/correction gates.

## Local AI/OCR resources

Local Ollama has vision-capable models installed:

- `qwen3-vl:4b`: fast primary pass.
- `llama3.2-vision:11b`: slower high-accuracy verifier.
- `minicpm-v:latest`: independent verifier.
- `moondream:latest`: lightweight verifier or unreadable-frame detector.

Qwen is useful, but it must not be trusted alone. The automated ground-truth path is model consensus plus deterministic checks.

### 3. Replace manual review with automated consensus labeling

Build an automated label adjudicator around the existing Ollama proposal files.

Inputs:

- Existing `labels_ollama_proposals.csv`.
- Fresh Qwen proposals.
- Fresh `llama3.2-vision:11b` proposals for disagreement/high-value rows.
- Optional `minicpm-v` or `moondream` proposals for tie-breaks.
- Existing temporal-neighbor anomaly flags.
- Plausibility ranges and monotonic/slow-changing field constraints.
- Current TinyML model predictions as another weak signal, never as sole truth.

Output:

- `labels_auto_consensus.csv` per batch.
- Promoted `labels_environment.csv` rows only when consensus confidence is high.
- Rows below confidence threshold stay excluded from training, not pending human review.

Consensus rules:

- Exact agreement between at least two independent vision models and temporal plausibility: promote.
- One-model result with strong temporal agreement across neighboring frames: promote as weak-auto.
- Any temporal jump, model disagreement, invalid range, missing display, or low confidence: exclude.
- Never train from a single unconstrained Ollama prediction.

Verifiable criteria:

- Pending review count no longer blocks training; rows are either auto-promoted or auto-excluded.
- Auto-promoted rows include provenance: source models, agreement level, temporal score, and timestamp.
- Dataset audit rejects rows without sufficient automated provenance.

### 4. Fix gas digit-position semantics programmatically

Implement deterministic handling for gas digit positions.

Approach:

- For CO2, emit visible digits left-aligned: `838` trains boxes 0, 1, and 2;
  `1498` trains boxes 0, 1, 2, and 3.
- For firmware and host full-frame evaluation, assemble CO2 as four digits only
  when the four-digit value is within the configured physical range; otherwise
  use the first three digits and ignore the fourth box's confidence.
- For HCHO/TVOC, retain the four displayed decimal digits but report raw values
  consistently with existing firmware scaling.

Verifiable criteria:

- Generated digit labels contain no synthetic zero-padding rows for 3-digit CO2.
- Full-frame field reconstruction handles both `838` and `1498` CO2 readings.
- Unit tests cover non-padded expected labels and ignored fourth-box confidence
  for 3-digit CO2 readings.

### 5. Generate negative/ambiguous examples without manual labeling

Programmatically create a negative set from existing images:

- Blur transforms.
- Overexposure/underexposure transforms.
- Cropped/partial display transforms.
- Occlusion masks over digit rows.
- Random non-display crops from frame margins/background.
- Existing failed/unlocatable captures.

These are labeled `valid=false` / `should_accept=false`.

Verifiable criteria:

- At least 100 negative/ambiguous rows exist.
- `reports/model_deployment_gate.json` reports `negative_set_present: true`.
- `false_accept_rate` is measured.

### 6. Retrain and evaluate in a closed loop

Run the training/evaluation loop after each automated data change:

1. Generate consensus labels.
2. Build digit dataset.
3. Train/export model.
4. Run crop-level evaluation.
5. Run full-frame evaluation.
6. Run deployment gate.

Verifiable criteria:

- No training run is accepted unless audit passes.
- Each loop writes metrics and mistake reports.
- The loop stops only when the deployment gate passes or when no automated improvement is available.

### 7. Remove firmware prototype paths only after metrics pass

Once the model and data gates pass:

- Raise firmware confidence threshold to the deployment target.
- Remove the temporary mounted-prototype humidity correction.
- Re-run firmware and host checks.

Verifiable criteria:

- `prototype_correction_removed: true`.
- `confidence_threshold: true`.
- Full deployment gate passes.

   agreement is already strong for CO2/temperature/humidity but weak for the two
   small decimal rows.
3. Add automated crop-quality filtering for consensus rows: reject rows whose
   pollutant digit crops have too little foreground, clipped bounds, or unstable
   neighboring values.
4. Produce mistake reports and montage images for the largest remaining
   CO2/HCHO/TVOC confusions, generated programmatically from predictions.
5. Retrain only after the consensus labels and crop filters change.
6. Accept a model only when `./scripts/verify_model_deployment.sh` passes.
